# Netmap NG — Audit & remediation plan (2026-05)

Source : 3 audits parallèles (Opus) sur la branche `claude/audit-project-security-120w3`
Dimensions couvertes : sécurité backend, gaps d'implémentation, frontend + DevOps/CI.

Le plan est **ordonné par phases** (P0 → P3). Chaque item est conçu pour être
exécuté par un agent Opus en autonomie : il porte un identifiant stable, des
fichiers cibles précis, l'action attendue et un critère d'acceptation.

## P0 — Hotfix critiques (à faire en premier, branchables séparément)

### P0-1 — `AUTH_DISABLED` ouvre un admin anonyme par défaut
- **Files** : `backend/app/auth/oauth.py:51-66`, `backend/app/auth/guards.py:15-23`
- **Bug** : `_has_role(user, role)` renvoie `True` quand `role==""` (cas par défaut sans `OAUTH_EDITOR_ROLE`/`OAUTH_ADMIN_ROLE` configurés). Combiné à `AUTH_DISABLED=true`, tout requête anonyme est éditeur+admin sur toutes les maps.
- **Action** :
  1. Dans `_has_role` : si `role` vide, renvoyer `False` (ne jamais accorder un rôle non configuré).
  2. Dans `oauth.py` : refuser le démarrage si `auth_disabled=True` sans flag explicite `DEV_ALLOW_NO_AUTH=1` **et** `APP_BASE_URL` localhost.
  3. Logger un warning de démarrage rouge si `AUTH_DISABLED=true`.
- **Critère** : test pytest qui fait un POST `/api/maps` sans cookie sur un app instancié avec `AUTH_DISABLED=true` et rôles non configurés → 401/403.

### P0-2 — Swagger UI exposé seulement quand l'auth est désactivée (logique inversée)
- **Files** : `backend/app/main.py:35`
- **Bug** : `docs_url="/docs" if get_settings().auth_disabled else None` — `/docs` est ouvert dans la pire des configs.
- **Action** : remplacer par un flag explicite `EXPOSE_DOCS` (default `False`) ; gater aussi `/openapi.json` et `/redoc`.
- **Critère** : `GET /docs` → 404 par défaut, y compris en `AUTH_DISABLED`.

### P0-3 — ID token OIDC jamais vérifié pour le provider générique
- **Files** : `backend/app/auth/oauth.py:96-120, 140-154`
- **Bug** : `isinstance(token.get("id_token"), dict)` toujours `False` (id_token est un JWT compact). En provider générique sans `server_metadata_url`, ni JWKS ni issuer ni audience configurés ⇒ aucune validation de signature ; les rôles viennent de `userinfo` non vérifié.
- **Action** :
  1. Imposer `OAUTH_DISCOVERY_URL` (server_metadata_url) ou exiger `OAUTH_JWKS_URL + OAUTH_ISSUER + OAUTH_AUDIENCE`.
  2. Parser le JWT avec `jwt.decode(token["id_token"], jwks, audience=client_id, issuer=expected_iss)` puis extraire les rôles depuis ces claims validés.
  3. N'accepter `roles` claim qu'en liste typée (rejeter le scalar string — voir L5 du rapport sécu).
- **Critère** : test unitaire avec un id_token forgé (mauvaise signature) → 401.

### P0-4 — Frontend Dockerfile expédie le serveur Vite **dev** en production
- **Files** : `frontend/Dockerfile`, `docker-compose.prod.yml:23-25`
- **Bug** : `CMD ["npm","run","dev"]`, `EXPOSE 5173`, `npm install` (non déterministe), base `node:25-alpine` (non LTS, n'existe sans doute pas). Compose prod attend nginx sur 80 → toute installation prod est cassée *et* expose HMR/source maps.
- **Action** : Dockerfile multi-stage `node:22-alpine` (builder, `npm ci`, `npm run build`) → `nginx:1.27-alpine` (runtime, `dist/` + `nginx.conf` durci, gzip, fallback SPA, `Cache-Control: immutable` sur assets hashés, `EXPOSE 80`, `USER nginx`).
- **Critère** : `docker compose -f docker-compose.prod.yml up` sert l'app sur :3000 ; `node_modules` absent de l'image.

### P0-5 — Versions GitHub Actions inexistantes (CI/Release silencieusement cassées)
- **Files** : `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.github/workflows/cleanup-images.yml`
- **Bug** : `actions/checkout@v6`, `setup-python@v6`, `setup-node@v6`, `upload-artifact@v7`/`v8`, `docker/login-action@v4`, `docker/setup-buildx-action@v4`, `docker/metadata-action@v6`, `docker/build-push-action@v7` — la plupart de ces majors n'existent pas (réels actuels : checkout v4, setup-node v4, login-action v3, etc.). À vérifier via `gh api` mais il y a très probablement plusieurs runs rouges.
- **Action** :
  1. Aligner sur les versions réelles (vérifier via `mcp__github__list_releases` ou `gh release list -R actions/checkout`).
  2. **Pinner par SHA** sur chaque action tierce (avec un commentaire `# v4.1.7`).
  3. Faire un dry-run `act` ou un PR test pour valider.
- **Critère** : workflow `ci.yml` vert sur PR test.

## P1 — Haute priorité (sécurité, intégrité, DoS, contrats)

### P1-1 — Sessions client-side cookie → store serveur Redis + idle timeout + rotation
- **Files** : `backend/app/main.py:43-49` (SessionMiddleware), `docker-compose.yml:42`
- **Action** :
  1. Remplacer Starlette `SessionMiddleware` par session serveur (lib `starsessions` ou impl maison) avec backend Redis (déjà dans compose mais inutilisé, voir CFG-1).
  2. Sliding expiry (idle 30 min, absolu 8h), rotation du session id à `login_callback` (anti session-fixation).
  3. Cookie : `Secure`, `HttpOnly`, `SameSite=Strict`, préfixe `__Host-` quand HTTPS, `path=/`.
- **Critère** : `Set-Cookie` post-login porte `__Host-`+strict ; après idle 30 min `/api/auth/me` → 401.

### P1-2 — CSRF sur tous les endpoints mutants
- **Files** : tous les routers `backend/app/api/*.py`, frontend `client.ts`.
- **Action** :
  1. Implémenter double-submit cookie (`csrf_token` côté cookie + header `X-CSRF-Token`) ou validation `Origin`/`Referer` + tokens SameSite=Strict.
  2. Côté frontend, `client.ts` injecte `X-CSRF-Token` sur POST/PUT/DELETE depuis un cookie non-HttpOnly dédié.
- **Critère** : POST sans header CSRF → 403 ; PR avec test e2e.

### P1-3 — `update_map` / `MapUpdate` typé strictement (Pydantic Literals)
- **Files** : `backend/app/api/maps.py:21-29, 117-133`
- **Bug** : `visibility: str | None`, `public_settings: dict | None`, `scales: dict | None` non bornés.
- **Action** :
  1. `visibility: Literal["private","internal","public"] | None`.
  2. `class PublicSettings(BaseModel): show_bps: bool, show_traffic: bool, show_node_names: bool, show_description: bool` (allow-list explicite, `extra="forbid"`).
  3. `class Scale(BaseModel): name: str = Field(max_length=64); min: float; max: float; color: str = Field(pattern=r"^#[0-9a-fA-F]{6}$")` ; `scales: list[Scale] | None`.
  4. Interdire `visibility="public"` via `update_map` ; passage public uniquement via `share_map`.
- **Critère** : tests Pydantic acceptent OK / refusent payloads malformés.

### P1-4 — Champs `extra` / `style` / `datasource` / `via_points` typés
- **Files** : `backend/app/api/nodes.py:24,26,40,42`, `backend/app/api/links.py:23,26-33,43-46,51`
- **Bug** : `dict` libres → DoS storage, sinks XSS (`info_url*`), bypass d'authz RRD via `extra.hostname`.
- **Action** :
  1. Modèles Pydantic : `NodeStyle`, `NodeExtra`, `LinkExtra`, `LinkDatasource` (Union discriminée `static`/`observium`/`rrd`), `ViaPoint`. `extra="forbid"` partout.
  2. `info_url*` : `AnyHttpUrl` ou regex `^https?://` (rejette `javascript:`/`data:`).
  3. Tailles bornées (`Field(max_length=...)`) sur tous les strings.
- **Critère** : tests négatifs (URL `javascript:`, payload 5MB, clé inconnue) → 422.

### P1-5 — `/api/datasources/traffic/history` (by-hostname) supprimé ou dérive serveur
- **Files** : `backend/app/api/datasources.py:108-148`
- **Bug** : authz par `link.extra.hostname == hostname` ⇒ l'éditeur contrôle `extra` donc l'authz est nulle ⇒ lecture cross-tenant des fichiers RRD.
- **Action** : supprimer la route `by-hostname` et ne garder que `/by-port` (`datasources.py:150-192`) qui résout `hostname/port_identifier` côté serveur depuis `observium_port_id_*`.
- **Critère** : route absente, frontend utilise `by-port` exclusivement.

### P1-6 — Filtre public maps : passer en allow-list
- **Files** : `backend/app/api/public.py:60-111`
- **Bug** : `_filter_node`/`_filter_link` deny-listent 3-5 clés ; tout nouveau champ sensible fuit par défaut.
- **Action** :
  ```python
  _PUBLIC_NODE_FIELDS = {"id","name","label","node_type","x","y","z_order",
                         "parent_id","width","height","icon","style"}
  _PUBLIC_LINK_FIELDS = {"id","source","target","label","line_style", ...}
  ```
  Projection explicite ; ajouter `public_settings.show_node_names` (default `False`) → si `False`, remplacer `name` par `label` ou hash. Idem pour `description` map.
- **Critère** : test unitaire qui ajoute un champ sensible aux modèles → ne fuit pas dans le payload public.

### P1-7 — Drift schémas front ↔ back
- **Files** :
  - `backend/app/api/maps.py:_serialize_node` (~ligne 279) : ajouter `locked`, `z_order`.
  - `backend/app/api/maps.py:_serialize_link` (~ligne 299) : ajouter `arrow_style`, `duplex`.
  - `backend/app/api/nodes.py:NodeCreate/NodeUpdate` : ajouter `locked`, `z_order`, `icon`.
  - `backend/app/api/links.py:LinkCreate/LinkUpdate` : ajouter `arrow_style`, `duplex`, `z_order`.
- **Bug** : ces champs roundtrip via état local mais sont droppés à chaque `loadMap`.
- **Action** : ajouter dans serializers + schemas Pydantic ; idéalement déclarer `response_model=` sur ces routes.
- **Critère** : test API : POST node avec `locked=true` → GET map → `nodes[0].locked == true`.

### P1-8 — `model_dump(exclude_none=True)` empêche d'effacer un champ
- **Files** : `backend/app/api/maps.py:130`, `backend/app/api/nodes.py:85`, `backend/app/api/links.py:84`
- **Bug** : `parent_id: null`, `info_url: null`, `bg_color: null`, `observium_device_id: null` envoyés par le frontend sont silencieusement ignorés.
- **Action** : remplacer par `model_dump(exclude_unset=True)` côté backend ; côté frontend, builder de payload qui n'inclut que les champs touchés.
- **Critère** : test API : PATCH node avec `parent_id: null` → GET → `parent_id is None`.

### P1-9 — Endpoint AI orphelin
- **Files** : `backend/app/api/ai.py`, `backend/app/main.py:104`, `frontend/src/api/client.ts:103`, `frontend/src/components/Editor/MapEditor.tsx:61`, `backend/app/config.py:55`
- **Bug** : router non monté mais code expose `api.generateMap`, bouton UI 404 ; pas d'`anthropic` dans `requirements.txt` ; envoie hostnames+ifAlias bruts à un LLM externe sans rédaction.
- **Action recommandée** : **suppression nette** (`ai.py`, `api.generateMap`, le bouton, la clé `anthropic_api_key` du config) sauf si la feature est priorisée — auquel cas : (1) ajouter `anthropic`, (2) remettre `app.include_router(ai_router)` derrière `require_editor`, (3) rédiger les hostnames avant envoi LLM.
- **Critère** : suppression — `rg ai_router|generateMap|anthropic` retourne 0 ou seulement les imports voulus.

### P1-10 — Pool MySQL Observium + batch des requêtes par port
- **Files** : `backend/app/datasources/observium.py:17-29, 132-147`, `backend/app/api/datasources.py:80-105`, `backend/app/api/public.py:124-146`
- **Bug** : 1 connexion par port × N links sequential ; pas de `connect_timeout`, pas de pool, pas de try/except ⇒ Observium HS = UI rouge entière.
- **Action** :
  1. `asyncmy.create_pool(minsize=2, maxsize=10, connect_timeout=5)` au démarrage.
  2. `get_ports_traffic_bulk(port_ids: list[int])` avec `WHERE port_id IN (...)`.
  3. Wrap toutes les fonctions du module dans `try/except asyncmy.errors.Error` → renvoie `None` ou liste vide ; côté API → 503 propre avec degraded data.
- **Critère** : Observium injoignable → load map fonctionne (graphes vides), pas de 500.

### P1-11 — Subprocess RRD bloquant l'event loop
- **Files** : `backend/app/datasources/rrd.py:74-86, 113-131`
- **Bug** : `subprocess.run(timeout=30)` synchrone dans un endpoint async ; pas de cap concurrence ; map publique ⇒ DoS trivial.
- **Action** :
  1. `await asyncio.to_thread(subprocess.run, ...)` ou `asyncio.create_subprocess_exec`.
  2. Bound concurrency : `asyncio.Semaphore(8)`.
  3. Cache résultats ~10s en mémoire (clé = `path|start|end|resolution`).
  4. Try/except `subprocess.TimeoutExpired`/`json.JSONDecodeError` → renvoie série vide (200 dégradé).
- **Critère** : 100 requêtes RRD parallèles ne bloquent pas l'event loop ni saturent le host.

### P1-12 — Rate limiting + body size limit
- **Files** : `backend/app/main.py`, `backend/Dockerfile`
- **Action** :
  1. Middleware `slowapi` ou maison : limites par IP sur `/api/public/*` (ex. 60 req/min) et par session sur `/api/*` (ex. 600 req/min).
  2. Body size middleware (`Content-Length <= 1 MiB` pour endpoints JSON, configurable).
  3. Configurer reverse-proxy (nginx/Traefik) avec `client_max_body_size 1m`.
- **Critère** : 200 requêtes consécutives en 10s sur public → 429 ; body 5MB → 413.

### P1-13 — Multi-stage backend Dockerfile + non-root + healthcheck
- **Files** : `backend/Dockerfile`, `docker-compose.yml`, `docker-compose.prod.yml`
- **Action** :
  1. Multi-stage : stage `builder` avec `build-essential librrd-dev` qui compile la wheel `rrdtool` ; stage runtime `python:3.12-slim@sha256:...` avec uniquement `librrd8 rrdtool`.
  2. `useradd -r -u 10001 netmap`, `USER netmap`.
  3. `HEALTHCHECK CMD curl -fsS http://localhost:8000/health || exit 1`.
  4. Compose prod : `read_only: true`, `tmpfs: [/tmp]`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`.
  5. Ajouter `backend/.dockerignore` (tests, __pycache__, .venv, .env, data/).
- **Critère** : `docker run --read-only ...` démarre ; `id` dans le container = uid 10001.

### P1-14 — Workflow permissions least-privilege + concurrency
- **Files** : `.github/workflows/ci.yml`, `.github/workflows/release.yml`
- **Action** :
  1. Permissions au niveau workflow → `contents: read` ; `packages: write` uniquement sur le job `docker`.
  2. `concurrency: { group: ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true }`.
  3. Job `docker` `needs: [backend-lint, backend-typecheck, backend-test, frontend-lint, frontend-typecheck, frontend-build]`.
- **Critère** : visualisation `gh run view` montre permissions restreintes par job.

### P1-15 — Release : SBOM + cosign + provenance
- **Files** : `.github/workflows/release.yml`
- **Action** :
  1. `anchore/sbom-action` ou `actions/attest-sbom` (SPDX).
  2. `sigstore/cosign-installer` + `cosign sign --yes ${IMAGE}@${DIGEST}` (keyless OIDC).
  3. `actions/attest-build-provenance` pour SLSA L3.
  4. Heredoc CHANGELOG : sentinelle `EOF=$(uuidgen)` au lieu de `EOF` littéral.
- **Critère** : `cosign verify ghcr.io/...` valide ; release page liste SBOM artefact.

### P1-16 — Validation CORS origins + alignement strict
- **Files** : `backend/app/config.py:37`, `backend/app/main.py:51-58`
- **Action** : valider chaque origin via Pydantic `AnyHttpUrl` ; refuser `*` quand `allow_credentials=True` ; refuser http en prod (sauf APP_BASE_URL=localhost).
- **Critère** : démarrage refuse `CORS_ORIGINS=*` en prod.

## P3 — Hardening / defense-in-depth

- **P3-1** Pinning Docker base par digest SHA dans tous les Dockerfiles.
- **P3-2** `cleanup-images.yml` : `min-versions-to-keep: 60`, exclure tags semver `vX.Y.Z`.
- **P3-3** `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `COEP`, `CORP` headers.
- **P3-4** Convertir secrets `Settings` (`oauth_client_secret`, `observium_db_password`, `app_secret_key`) en `pydantic.SecretStr`.
- **P3-5** Réduire log OAuth callback (suppression du log des session keys, oauth.py:94).
- **P3-6** Ajouter `.gitignore` pour `frontend/tsconfig.tsbuildinfo` ; supprimer le fichier suivi.
